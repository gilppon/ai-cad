# APPI 도면 보관·파기 정책 (STATE Phase 3.3)

> 본 문서는 일본 APPI(個人情報保護法) 대응용 운영 정책이다. 코드 게이트와 함께 운용한다.

## 1. 원칙

- 고객 도면(PDF·IFC·텍스트층)은 **개인정보·영업비밀이 포함될 수 있는 취급주의 데이터**로 간주한다.
- 저장소(git)·로그·벡터DB에 도면 원본·실발주처 식별정보를 잔류시키지 않는다.

## 2. 저장 위치

| 데이터 | 저장소 | git 추적 | 비고 |
|---|---|---|---|
| 업로드 원본 | `./uploads/` (운영: 외부 볼륨/오브젝트스토리지로 분리) | 금지 (`.gitignore:37`, CI 게이트) | 컨테이너 재기동 시 소실 가능 — 운영 볼륨 필수 |
| 산출물 | `./out/` | 금지 | 동일 |
| 벡터DB | `vector_store/` | 금지 (`.gitignore:44`) | 법령 코퍼스만 포함, 도면 임베딩 혼입 금지 |
| 세션 | `sessions/` | 금지 | 동일 |
| 테스트 픽스처 | `tests/fixtures/` (마스킹 후, 대표님 승인분만) | 허용 (마스킹본만) | 실발주처 정보 포함 시 편입 금지 |

## 3. 보관기간·파기

- 기본 보관: 프로젝트 완료 후 **90일**. 기간 경과 시 원본·산출물 삭제 (バッチ 또는 수동, 삭제 로그 보관).
- 고객 요청 시 즉시 삭제 (삭제 완료 통지).
- 로그: 도면 바이너리·Base64를 로그에 출력하지 않는다. 요청ID·project_id·판정결과 메타만 기록.

## 4. 게이트 (CI/출항)

```bash
git ls-files | grep -E "uploads/|vector_store/|sessions/"  # = 0 이어야 함
grep -rn "mock_" web/src  # = 0
```

## 5. 잔여 과제

- `uploads/` 5건 합성픽스처의 git 히스토리 정리 여부: 실발주처 정보 없음 확인 후 판단 (`filter-repo`는 되돌릴 수 없음).
- 운영 스토리지 분리 (S3/GCS + 서명 URL) — Phase 3 잔여.
